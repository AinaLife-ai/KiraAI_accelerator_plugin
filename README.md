# KiraAI 加速器（kira_accelerator）

**让 KiraAI 反应更快，而且不牺牲质量、不破坏你装的其它插件。**

> 一句话：它解决的是「为什么 KiraAI 比别的框架慢」这个问题。
> 装上之后，你发一条消息，**不用等它把整段话想完才看到第一个字**。

---

## 它治的是什么病

如果你用过 KiraAI，可能有这些感受：

- 🐢 发完消息要**干等十几秒**，屏幕一直没动静，然后突然整段话蹦出来
- 🐢 让它查个东西（要用工具），要等**更久**
- 🐢 有时候它明明能秒答「在的」，却也要想半天
- 🐢 用久了越来越卡

这些**不是你的模型慢**，是框架的调用方式决定的。这个插件就是来修这个的。

---

## 装什么、怎么装

1. 下载 `kira_accelerator` 文件夹（或 zip 解压）
2. 放进 KiraAI 的 `data/plugins/` 目录
   ```
   data/plugins/
   └── kira_accelerator/
       ├── main.py
       ├── manifest.json
       ├── schema.json
       ├── icon.png
       ├── wallpapers/          ← 24 张动漫壁纸
       └── web/                 ← 侧边栏面板
   ```
3. 重启 KiraAI（或在 WebUI 里热重载插件）
4. 在插件管理里**启用**
5. 侧边栏会出现「**加速器**」，点进去

> ⚠️ **所有开关默认都是关的。** 这是刻意的——请按下面的「建议开启顺序」一步步来，
> 每开一项都看一眼面板数据。**不要一次全开。**

## 核心功能（按推荐开启顺序）

### ① 观测（默认开，零风险）

记录每一轮的耗时、抢先发送了多少段、思考开没开。
**先开这个跑几天**，看你的实际情况再决定后面的。

### ② 强制流式 ⭐ 提速最关键的一项

KiraAI 默认是「等模型把整段话写完，再一次性给你」。
开启后改成「**边写边收**」——不管你的模型提供商本身怎么设置，一律走流式接口。

**效果**：不再有整段空等；首字时间从「整段生成时间」降到「第一句话的时间」。

### ③ 抢先发送 ⭐ 感知提升最明显的一项

配合上面的流式。模型每写完**一个完整的消息段**（一个 `<msg>`），
就**立刻发给你**，而不是攒齐了再发。

**效果**：以前你要等 12 秒才看到全部；现在大约**1 秒就能看到第一句**。

> 这两个是收益最大的。建议先用「生效提供商」填**一个**做灰度测试，
> 确认没问题再全开。

### ④ 自动按需思考 ⭐ 该想的时候才想

有些问题需要模型「认真想想」（比如问原理、让你分析代码），
有些完全不用（比如「在吗」「哈哈」）。

开启后，插件会**自动判断**：简单寒暄直接不思考（更快、更省 token），
复杂问题才开深度思考（质量更好）。

**判断依据**（五个信号打分）：有没有复杂意图词、上一轮工具是不是失败了、
可用工具多不多、上下文长不长、你的消息长不长。

**五种厂商风格可选**（不同家的参数名不一样，选错会被忽略）：

| 风格 | 适用 |
|---|---|
| `compatible`（默认） | 大多数兼容网关 |
| `reasoning_effort` | OpenAI o 系列 |
| **`deepseek`** | **DeepSeek V4（只有 high/max 两档，插件会自动映射）** |
| `enable_thinking` | 通义 / 阿里系 |
| `thinking_object` | Anthropic / 部分网关 |
| `vllm_chat_template` | vLLM 部署的通义 |

### ⑤ 请求优化 · 底层接管（进阶，按需）

| 选项 | 作用 | 风险 |
|---|---|---|
| 收敛发送节流 | 去掉多段消息之间 2~5 秒的等待，**解除会话被卡住** | 低 |
| 复用 HTTP 客户端 | 不再每个步骤都重新建连接 | 低 |
| 记忆落盘异步化 | 把写硬盘挪出主流程，**治「越用越卡」** | 中（建议先备份 `data/memory/chat_memory.json`） |

### ⑥ 外观 · 皮肤轮换

- **24 张动漫壁纸**自动轮换（默认 30 秒一张）
- **切换特效可选**：晕染（默认，像墨在纸上渗开，**每次中心位置随机**）、
  柔和晕染、燃开（带暖色焦痕）、淡入淡出、直接切换
- **点缩略图挑选**：只选 1 张 = 固定不轮换；不选 = 全部参与
- 可以一键关掉，回到纯深色背景
- **把你自己的图丢进 `wallpapers/` 目录就会自动加入轮换**

## 安全性：它不会搞坏你的 KiraAI

这是设计时最优先考虑的事。

### 三条铁律

| 铁律 | 意思 |
|---|---|
| **幂等** | 插件重载时不会重复叠加自己的改动 |
| **精确还原** | 卸载时只还原「确实是自己装的」那些改动，**别人改过的不碰** |
| **熔断 + 自动恢复** | 某个接管点连续出错 3 次就临时停用它；**冷却 30 秒后自动试探恢复**；失败则冷却时间翻倍（最长 10 分钟一次）。**任何时候都能在面板点「立即重置」** |

> 熔断**不是永久关闭**。它是「先让它歇一会，再自己试试能不能恢复」。
> 一次网络抖动不该让功能永久失效。

### 出问题会怎样

- 任何一个优化项出异常 ⇒ **立刻回落到 KiraAI 原本的实现**，对话照常
- 面板上「底层接管点健康度」会显示每个点的状态：`生效` / `熔断中 · Ns 后试探` / `未启用`

### 与其它插件的兼容

我们用**真实源码**测过插件市场上 7 个较活跃的插件（版本逐一比对，均为最新）：

| 插件 | 我们做的避让 |
|---|---|
| Sustained Chat 可持续聊天 | 它用 HIGH 优先级，我们用 **SYS_LOW**（最低）⇒ 永远最后执行，不抢 |
| Default Chat（z） | 同上 |
| Midflight 随时插话 | 它读 `tool_result.text`，我们**只读不改** |
| KSM 会话合并与互通 | 它订阅 `ON_MESSAGE_SENT` ⇒ 我们抢先发送时**补广播**这个事件 |
| Anti Harass 防骚扰 | 同上 |
| Model Fallback | 它读 `client.model.*` ⇒ 我们的代理层**原样透传** |
| SubAgent | 它会**并发**用同一个客户端 ⇒ 我们的递归护栏用 task-local，不误判 |

## 常见问题

**Q：装了就一定会变快吗？**
A：流式相关的一定有效果。但**具体快多少取决于你的模型和网络**。
先开「观测」跑一段时间，面板上的「首段发出耗时」会告诉你实际情况。

**Q：会不会影响回答质量？**
A：不会。抢先发送**只改变发送时机，一个字都不改**。
自动思考确实会改变「想不想」，但它只在简单寒暄时省掉思考——复杂问题照样深度思考。

**Q：要重启吗？**
A：改配置**不用**。面板上点保存就等于热重载。
（例外：KiraAI 自己的 `bot_config` 那些参数改了要重启，那不是本插件管的。）

**Q：「熔断」了是不是坏了？**
A：不是。它在休息，会自己试着恢复。
急着用就点面板上的「立即重置」。

**Q：想换壁纸怎么办？**
A：把你的图（webp/jpg/png）丢进 `wallpapers/` 目录，面板里就会自动出现。

## 配置在哪

**侧边栏「加速器」面板里全部可视化配置，保存即热生效。**

不用手动改任何配置文件——面板上每个选项都有中文说明，改完点「保存并热重载」即可。

（同样的配置项也存在于 KiraAI 的插件配置页，两处是同一份数据。）
